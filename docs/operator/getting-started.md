# Operator Handbook — Getting Started

Audience: on-call operators and maintainers of the zaffiliate production deployment.

## Topology (what is running where)

- Public entry: `https://zaffiliate.zeaz.dev` → Cloudflare edge → locally-managed Cloudflare tunnel `77107d8b` (config `/etc/cloudflared-zaffiliate/config.yml`) → loopback Caddy vhost (`:80/:8080`) → API systemd unit `zaffiliate.service` on `:8788`.
- Data: Supabase Postgres (project `dryflnsxhjuaamnzfrtu`, ap-northeast-1) via IPv4 session pooler; 18+ RLS-forced tables; migrations in `db/migrations/` applied by the checksummed migrator.
- Control Plane UI served by `apps/web` behind the same edge.

## First five minutes on an incident

1. Health: `curl https://zaffiliate.zeaz.dev/healthz` → expect 200 `{"ok":true}`.
2. Version/commit: `/api/v1/version` → confirm expected release.
3. Readiness detail: `/readyz` (503 = dependency problem, read `reason`).
4. Metrics: `/metrics` — scrape into your local prometheus for a look.
5. Stop-the-line if needed: see `incident-response.md`.

## Non-negotiables

- Never edit production data with direct SQL outside documented emergency procedure (`financial-reconciliation.md`).
- Never bypass tenant headers when exercising APIs; every `/api/v1/*` call needs `x-tenant-id`.
- Never merge red CI; never interpret missing checks as green (repo merge policy).
